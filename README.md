# ICMS / Contrlio 企业内控管理系统

**以业务流程为主线，连接风险、控制、检查证据与整改复核。** ICMS 为企业内控团队提供设计、记录、监督和追踪工作台，帮助管理者从风险回到流程、从发现跟到验证关闭。

## 一条可追溯的管理链

```mermaid
flowchart LR
  A[公司 / 部门 / 责任] --> B[业务流程]
  B --> C[风险与控制目标]
  C --> D[控制措施 / RCM]
  D --> E[检查与真实证据]
  E --> F[发现与整改]
  F --> G[独立复核 / 重测 / 关闭]
  G --> H[工作台与报告]
```

平台强调责任到人、公司范围授权、证据关联和整改验证。它不替代 ERP、POS、支付或审批执行系统；流程配置的发布也不会自动启动待办、通知或实际审批。

## 主要应用价值

- **风险有上下文**：从业务流程关联目标、风险、控制措施和测试程序，便于负责人识别控制覆盖缺口。
- **检查有依据**：保存检查期间、执行人、程序、样本说明、结论和实际证据，支持复查。
- **整改能验证**：维护责任人、期限、提交版本、独立复核和重测；失败可退回，未通过验证不能直接关闭。
- **管理看真实记录**：Dashboard 和报告根据当前公司业务数据聚合，减少依赖手工汇总。
- **起步有参考**：行业资料提供流程、风险、控制、制度和实施建议，企业需结合实际校准。
- **AI 有边界**：AI 为可选能力；制度内容外发到公司配置的模型服务商前逐次确认，输出需人工复核。

## 技术架构

| 层 | 当前实现 |
|---|---|
| Web | Next.js 15.5、React 19、TypeScript 5.8 |
| API | Python 3.11+、FastAPI、Pydantic、SQLAlchemy 2、Alembic |
| 业务记录 | PostgreSQL 16 |
| 证据及制度原件 | MinIO 私有对象存储，PostgreSQL 保存元数据和 SHA-256 |
| 会话状态 | Redis 保存撤销等轻量状态，不作为业务事实源 |
| 权限 | Argon2、JWT、HttpOnly Cookie、公司 membership 与 RBAC |

系统按公司隔离业务访问；API 在读取、写入、关联和文件下载时校验组织范围。完整架构、数据流和实现边界见[系统作品说明](icms/docs/GITHUB_SHOWCASE.md)与[架构文档](icms/docs/ARCHITECTURE.md)。

## 菜单模块

工作空间包括工作台、公司与成员、部门、行业参考库、法规与流程合规、制度合规分析及 AI 内控助手；体系建设包括业务流程、风险库、控制库和风险控制矩阵；监督整改包括内控检查、证据库和整改闭环；另有内控报告、用户管理与账号设置。

## 企业实务演练

作品说明包含两个明确标注为**模拟情境**的场景：供应商准入与食材验收，以及连锁门店退款与收银日结差异。后者演示了“18 笔 POS 退款、15 笔支付平台原路退款、3 笔未关联原订单、现金交班差异待查”的分析路径，再通过真实证据、整改计划、独立复核和后续重测形成闭环。它们不是客户实绩或真实损失记录；系统当前也不直接连接 POS/支付平台自动对账。
