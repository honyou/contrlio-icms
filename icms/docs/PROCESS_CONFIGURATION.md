# 业务流程配置

在「业务流程」新建流程档案，然后点击清单中的「配置流程」。经理和系统管理员可以修改及发布；其他公司成员可以查看。流程配置只属于当前公司，并关联当前流程的风险和控制。

## 配置内容

- 流程目的、适用范围、触发条件、办理频率、输入材料、输出成果和异常处理规则。
- 办理表单：文本、多行文本、数字、日期、下拉选项及勾选字段，可设置必填。
- 流程步骤：任务、审批和条件分支，可调整顺序、负责部门、经办人、办理时限和证据要求。
- 审批规则：任一人审批、全员审批或顺序审批，顺序模式按选定审批人次序配置。
- 内控关联：步骤可关联当前流程的风险及控制；跨公司、跨流程关联会被拒绝。
- 条件分支：根据表单字段进行比较，设置命中去向和默认去向；只允许流转到后续步骤或结束。
- 预览：查看表单、步骤和流转关系；已发布快照与历史版本可独立查看。

「生成起步草稿」按该流程的实际档案、风险、控制和 RCM 检查程序填入可编辑配置，包含受理、审批、执行控制、异常分流、正常归档和异常跟踪。审批人需结合实际授权填写，生成不会自动发布。

## 保存与发布

保存草稿会写入 PostgreSQL 并递增修订号。发布前系统检查目的、范围、触发条件、输入输出、异常处理、责任分配、审批人员、分支字段类型、证据说明和节点可达性。发布生成独立快照，后续草稿修改不会覆盖历史版本。

保存和发布都检查客户端读取时的修订号，防止多窗口编辑互相覆盖；发生冲突时需重新加载当前数据再编辑。同一修订号不能重复发布。

流程清单显示步骤数和「待配置」「草稿」「已发布」「有未发布修改」状态。每个流程最多 50 个表单字段、60 个步骤、每个条件步骤 20 个分支；接口显示最近 20 个发布版本，数据库保留全部发布记录。

当前模块完成流程设计、配置持久化及版本发布。发布并不自动启动业务审批、生成待办、发送通知或执行超时提醒；配置中的时限和审批模式保存为流程规则。

## 数据升级

执行 `uv run alembic upgrade head` 建立 `process_configurations` 和 `process_configuration_versions` 表，原有流程档案及关联业务资料保留。新应用的行业样例包含可编辑的流程配置草稿。已有流程可在编辑器中生成起步草稿；仅在实际保存后写入数据库。

## 接口

所有接口都需登录，并提供 `organization_id` 查询参数：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/processes/{id}/configuration` | 读取草稿、当前发布快照及历史 |
| GET | `/api/processes/{id}/configuration/template` | 按实际关联资料生成起步配置，不写入数据 |
| PATCH | `/api/processes/{id}/configuration` | `{expected_revision, config}` 保存草稿 |
| POST | `/api/processes/{id}/configuration/publish` | `{expected_revision}` 校验并发布已保存草稿 |

保存和发布同时记录审计事件。只读访问不会创建配置记录。
