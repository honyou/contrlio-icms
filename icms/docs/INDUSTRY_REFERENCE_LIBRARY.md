# 行业内控参考库

研究和更新日期：2026-10-02。当前参考库包含 14 个行业/通用场景、3 个实践层级，共 42 套可浏览模板。食品饮料与连锁餐饮每套均展示 8 条端到端流程，其余行业每套均展示 5 条流程。阶段决定控制设计深度和抽样提示；应用到公司工作区时，起步型、成长型、体系型分别导入 1、2、3 条阶段流程作为可编辑草案。公司可继续新增流程。每套模板提供组织建议、岗位职责、制度包、分阶段工作方案、行业专项控制、流程/风险/控制/抽样示例、公开来源，以及明确标注的模拟实施案例。经理可把选定的基础流程和检查计划写入当前公司数据库；Evidence、Finding、测试结论和整改不会由样例伪造。

参考库采用“官方框架和监管资料 + 按行业经营流程改写 + 经公开来源核实的案例 + 虚构演练案例”的结构。系统中“起步型/成长型/体系型”是控制设计的练习路线，不是行业成熟度调查、合规认证、强制标准或样本量准则。

## 如何使用

1. 在浏览器进入“行业参考库”，选行业，再选起步型、成长型或体系型。
2. 浏览“组织框架与职责”，按公司规模选择治理模型；把系统示例部门映射到真实部门/岗位。
3. 在“具体制度与控制”复制通用授权、证据、问题整改条款和行业专项制度，补入公司名称、权限金额、责任岗位、数据保存期限、升级时限和本地监管要求，再走公司正式审批。
4. 依“工作方案与论证”先选 2–3 条高风险端到端流程试点，核实总体完整性，运行至少一个真实业务周期；根据失败项创建 Finding/Issue，要求责任人上传真实整改证据，由独立复核人复核和重测。
5. 公开案例用于学习控制失效机制；模拟案例只用于培训/演练，不代表任何真实公司事件。来源司法辖区不同，制度套用前检查适用主体和现行规定。
6. 可导出当前行业和实践层级的 Markdown 实施手册。应用模板会在 PostgreSQL 产生公司所有的基础控制体系记录，Evidence 文件仍须真实上传 MinIO，Dashboard 从实际公司记录聚合。

## 内控组织框架与职责

组织要解决的是“谁拥有业务控制，谁监督执行，谁能独立提出问题”。业务流程负责人拥有风险和控制；内控协调人统一方法、维护矩阵和推动缺陷整改；独立复核/内部审计不得替代管理层执行控制，也不应复核自己设计或执行的工作。小公司可由现有岗位兼职，但应设置可落地的补偿性复核和独立升级路线。

|规模示例|组织结构|关键约束|
|---|---|---|
|小型单体公司|负责人 → 流程负责人/控制执行人；财务或兼职内控协调人维护台账；指定未参与交易的人按月检查关键例外|无法完全分岗时，复核须覆盖完整例外总体，记录审阅人、日期、异常和处理；重大事项可直接上报负责人/所有者|
|成长型、多部门公司|董事会/负责人 → 管理层风险或内控会议 → 内控协调职能 → 部门流程责任人；内部审计按风险计划独立评价|业务部门执行控制；协调职能维护方法、质量检查和整改跟踪；内审不得承接被审流程日常控制|
|集团、上市或受监管主体|董事会/审计委员会 → 管理层内控委员会 → 集团风险/合规/内控职能 → 子公司和业务控制负责人；内审独立向治理层报告|集团最低标准与当地监管矩阵并行；外部审计不替代管理层责任；利益冲突和重大缺陷按治理机制升级|

RACI 记号：R 为执行；A 为最终负责；C 为协商；I 为知会。系统手册中为每项活动显示六类角色的分工表。最低建议是：治理层批准风险偏好、重大制度和剩余风险；管理层提供资源；业务负责人拥有流程和控制；一线执行人同期留存证据；协调人维护方法和跟踪；独立人员测试、复核、重测。

## 通用制度包（可编辑示范，不是法规原文）

### 1. 授权审批与岗位制衡

- 维护按事项、金额和风险划分的授权矩阵，覆盖合同、采购、付款、折扣/退款、账户/主数据修改和资产处置；每年和组织变化时复核。
- 申请须列明目的、预算/合同依据、交易对手及附件；审批人检查权限、预算、必要性、利益冲突和证据。紧急口头批准在规定时限内补录并由非申请人复核。
- 尽可能拆分申请、供应商建档、验收、付款制单、付款批准和银行对账。小团队不能拆岗时，设补偿性复核，按月检查完整例外清单并留痕。
- 禁止拆单绕权限、共享审批账号和倒签；代理权限写明期限和范围；越权、关联方或预算外事项逐级升级。
- 留存授权表版本、申请审批日志、代理记录、岗位不相容表、例外分析和跟进记录。

### 2. 风险、控制、抽样与证据留存

- 每个业务流程指定负责人，描述流程边界、目标、风险、可能性/影响及判断依据、现有控制和剩余风险。风险评分辅助排优先级，不能替代判断。
- 关键控制说明时点、频率、责任人、复核标准、例外路线、证据位置及保存规则；避免“加强管理”这类不可测试表述。
- 检查前确认测试总体完整，保存来源报表、期间和筛选条件；按风险分层选样本，覆盖新流程、异常、高价值、高风险时段和期间边缘，写明抽样方法和局限。
- 证据应来自实际业务执行，能识别日期、样本、执行人、复核结论和来源。截图需含系统/期间/筛选上下文；访谈不替代交易原始凭证；不得以事后补制材料冒充同期记录。
- 至少年度重评，并在组织、产品、系统、供应链、法规或外包重大变化时触发更新。保存风险登记册、RCM、总体完整性核对、样本、测试底稿和原始记录。

### 3. Finding、Issue、整改、复核、重测与关闭

- Finding 记录可验证事实、控制要求、样本编号、潜在影响和严重度判断；严重度考虑金额、人员/安全、监管影响、重复、范围和扩散可能。
- 重大数据泄露、财务舞弊、安全或监管时限事件立即升级，先遏制和保存日志，记录报告责任人和下一次更新时间。
- Issue 整改计划必须有根因（而非重述表象）、纠正措施、系统性预防措施、责任人、资源、到期日、临时控制和完成标准；延期说明原因并经有权人批准。
- 责任人提交实施证据后，由未执行该措施的独立人员复核；复核通过后由独立检查人重做可重演测试。失败退回并保留版本。
- 只有整改证据、复核通过、重测通过和所需剩余风险批准齐备时才能关闭；Dashboard 统计实际状态。月度关注逾期、重开、重复根因和超期风险接受。

## 12 周实施工作方案与论证

下表是产品内可改的项目计划样例，不是监管期限。其论证是先验证事实和责任，再发布可测试控制，之后以样本运行、独立复核证明执行，最后以真实问题闭环迭代。应按复杂度、季节性和资源调整。

|时间|牵头人|主要工作和交付|验收点|
|---|---|---|---|
|第 1–2 周：定边界和责任|企业负责人、内控协调人、部门负责人|核实主体、地域、许可和集团关系；确定优先流程、风险升级路线、授权矩阵草案；访谈一线、走查流程、收集系统和台账|每个试点流程有负责人、边界、关键系统和总体来源；待核法规事项有责任人和期限|
|第 3–4 周：风险评估和制度定稿|流程负责人主责；协调人组织；法务/财务/安全复核|形成风险登记册、岗位不相容分析；定稿授权/证据/异常整改制度；建立 RCM，定义频率、人员、证据、总体和程序|高优先级风险都有控制或正式风险接受；关键控制可由另一人依证据重演|
|第 5–8 周：真实流程试运行|流程负责人、执行人；协调人督导|选 2–3 条高风险流程运行至少一个周期；从完整总体选样；保存来源、选择依据、原始证据和偏差；创建 Finding/Issue 并指定整改|完成一次可复演检查；记录来自真实交易；偏差有根因、责任人、期限和临时控制|
|第 9–12 周：复核、重测、扩展|独立复核人/内审；负责人主持复盘|独立审阅整改证据并重测；分析逾期、重复发现、例外、证据缺失和权限冲突；提交年度计划和未解决风险|Issue 关闭具备完整证据、复核、重测轨迹；未解决风险有正式接受/升级；Dashboard 可追溯到数据库记录|

管理层宜观察优先流程负责人覆盖、同期证据可获得率、例外数量及处理时长、逾期 Issue、复发率、权限复核完成度、抽样重测通过/失败和重大风险变更等趋势。指标目标由公司设定；不可将高通过率单独当成控制有效证明，也不可鼓励隐瞒缺陷。

## 公开案例与模拟案例的证据纪律

目前收录 10 个一手公开材料案例：食品 Blue Bell 食安检测/通知失效；零售 Stein Mart 存货永久折价与财务沟通失效；物流医疗物资配送商 SRI Surgical Express 的发运确认与实际交付记录漏洞；建筑工程 Granite 项目完工成本预测指控；医疗 Affinity 退租设备前未清除病历数据；SaaS/HIPAA 商业伙伴 MMG Fusion 风险分析与数据泄露处置；专业服务集团 Hill International 会计差错处理；银行 Wells Fargo OCC 合规风险管理同意令；教育资助付款流程 GAO 审计；能源电力丰城电厂施工平台事故调查。案例页面直接链接至 SEC、HHS、美国司法部/GAO、中国应急管理部或对应监管机关的一手文件。

程序状态须区分：Granite SEC材料基于诉状中的指控；Hill资料记载同意判决过程；Wells Fargo OCC同意令记载监管认定且银行不承认也不否认；Blue Bell公司对食品安全指控认罪；丰城案例为国务院事故调查报告。案例不是对应用户企业的合规判断或行业发生率。

其他行业暂未收录足够匹配且经一手来源核实的执法案例时，系统明确显示“未收录公开执法案例”，只提供注明虚构的模拟情境。模拟故事展示控制链的可能断点，供演练流程使用，不是全网真实企业事件，不可引用为行业事故统计或违法事实。

## 研究限制、法规边界及版本维护

- “全网检索”不是也不可能涵盖所有企业内部制度。多数企业内控材料不公开；参考库只能基于可访问的公开法源、官方框架、监管指导和公开执法/审计材料形成可说明来源的起点。
- 公开材料的司法辖区、主体类别、生效日期、行政/诉讼程序状态不同。美国 SEC/HIPAA、美国 FDA 资料用来解释风险机制，不能直接套成中国企业义务；地方预售资金材料仅示例当地制度；部分历史法规页面需要核对现行有效版本。
- 使用者应确认主体规模和类型、行业许可证、所在国家/省市、上市/集团属性、客户合同和数据类别，必要时请本地法律、财务、安全和行业人员复核。系统条款不是法律意见、审计结论或监管承诺。
- 抽样数量仅为方案参考；真实审计须依据总体完整性、频率、风险、控制目的和适用审计准则确定样本。样本通过不自动证明所有期间均有效。
- 当前阶段重点是本地内控业务系统和参考内容质量；不会把本手册建设目标变成生产云部署工作。
