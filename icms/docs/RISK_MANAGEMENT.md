# 风险管理

「风险管理」由公司用户自行维护风险台账，并按实际业务流程组织展示。系统提供 14 个行业的基础风险模板作为填写参考；模板不会自动创建、覆盖或替代公司风险。

## 使用方式

1. 在风险台账一级菜单按实际业务流程查看风险点和重要等级；流程下没有风险时显示「尚未填写风险」。
2. 点击风险点进入二级详情，查看或维护关联控制、核查手段、检查程序、证据要求、责任岗位和剩余风险。
3. 点击「新增风险」由用户填写风险编号、名称、所属流程、描述、评分、核查安排和责任岗位后保存。
4. 在「行业参考模板」中选择行业，查看对应流程和具体风险；可将单个参考风险带入填写表单，但仍需用户补充、修改并确认保存。
5. 在风险台账按流程、风险等级、类别、状态或关键词筛选。风险接受、应对、关闭通过状态迁移记录留痕。

模板覆盖食品饮料与连锁餐饮、制造、电商与零售、软件与信息技术、物流、建筑工程、医疗服务、专业服务、金融服务、物业、教育、农业、能源公用事业和通用企业。食品饮料与连锁餐饮提供 8 个基础流程，其余行业提供 5 个基础流程；每个流程至少 3 项具体风险，企业可以另行建立流程和自定义风险。

## 风险评估

固有风险分数 = 发生可能性 × 影响程度，两项均为 1–5 分。

| 分数 | 风险等级 |
|---|---|
| 1–4 | 低 |
| 5–9 | 中 |
| 10–16 | 高 |
| 17–25 | 严重 |

评分依据在页面的评估说明中查看。模板评分是起步建议，企业应结合交易规模、异常历史、业务复杂度及风险承受程度调整。

剩余风险指控制运行后的风险，需要另行填写可能性和影响两项评分；未评估时显示「未评估」。导入模板不会自动将控制视为有效，也不会自动产生已完成的检查、真实证据或风险接受结论。

## 权限与持久化

公司成员可查看本公司风险台账和行业模板。公司经理及系统管理员可以新增、编辑风险档案并作出处置决定。所有关联校验都限定在同一公司及同一业务流程中，跨公司引用会被拒绝。行业参考内容只在浏览器表单中作为预填建议，用户确认保存后才会写入公司台账。

风险档案变更保留审计记录。关联控制和检查程序沿用控制措施、RCM 与内控检查模块，后续核查仍需要实际执行并保留证据。

## 升级

在 API 目录执行：

```bash
uv run alembic upgrade head
```

迁移为原有风险增加核查指导和模板来源字段。已有风险数据保留；已有公司可以浏览合适行业的基础模板并逐项参考填写。新建公司时行业参考库仍可用于初始化组织示例，但风险管理页面本身不会自动写入模板风险。

## 接口

接口需要登录并指定 `organization_id`：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/risk-management` | 风险台账、业务流程、关联控制及计算等级 |
| GET | `/api/risk-templates` | 行业基础风险模板和评估尺度 |
| POST / PATCH | `/api/risks`、`/api/risks/{id}` | 新建或修改企业风险档案及核查指导 |
| PATCH | `/api/risks/{id}/status` | 按状态迁移规则记录风险处置决定 |

风险保存请求包含实际 `process_id`，以及风险描述、评分、核查手段、证据要求和责任岗位等用户填写内容。行业模板接口仅返回参考数据，不代表公司已采用或完成风险评估。
